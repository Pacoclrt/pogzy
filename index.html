Démarrer / Installation & outils

Installation & outils

Go se compile en une seule commande, sans configuration. Trois outils suffisent pour tout le manuel.

Les commandes du quotidien

terminall'essentiel
go version          // vérifie que Go est installé
go run main.go      // compile en mémoire puis exécute — 90 % du temps
go build main.go    // produit un exécutable dans le dossier courant
gofmt -w main.go    // réécrit le fichier avec l'indentation officielle
go vet main.go      // signale les erreurs que le compilateur laisse passer
go run main.go
go
L'outil unique du langage : compilation, tests, formatage, gestion des paquets.
run
Compile en mémoire et lance immédiatement. Aucun fichier binaire n'est laissé derrière.
main.go
Le fichier à exécuter. Il doit contenir un paquet main et une fonction main.

Organiser un projet

Un dossier, un fichier go.mod, et c'est parti. Le module déclare le nom du projet et permet aux imports de se résoudre.

terminalcréer un projet
mkdir mon-projet && cd mon-projet
go mod init mon-projet
go get github.com/01-edu/z01     // ajoute le paquet d'affichage au projet
gofmt n'est pas optionnel

Go impose un style unique : tabulations, accolades collées, espaces normalisés. gofmt -w reformate le fichier en place. Prends l'habitude de le lancer après chaque modification — c'est ce que fait automatiquement tout éditeur configuré pour Go.

Démarrer / Structure d'un programme

Structure d'un programme

Tout fichier Go a exactement trois étages : le paquet, les imports, le code. Dans cet ordre, sans exception.

main.goprogramme minimal
package main

import "github.com/01-edu/z01"

func main() {
	z01.PrintRune('H')
	z01.PrintRune('i')
	z01.PrintRune('\n')
}
sortieHi

Anatomie

Ligne par ligne
package
Mot-clé obligatoire, première ligne du fichier. Il déclare à quel paquet le fichier appartient.
package main
main est le nom réservé du « programme exécutable ». Go cherche alors une fonction main() et la lance. Tout autre nom produit une bibliothèque : du code destiné à être importé ailleurs, sans point de démarrage.
import
Charge un paquet extérieur. Sans cette ligne, le nom z01 n'existe pas.
"github.com/01-edu/z01"
Le chemin du paquet, entre guillemets doubles. Le nom utilisable dans le code est le dernier segment : z01.
func
Déclare une fonction. En Go, tout code exécutable vit dans une fonction.
main()
Le point d'entrée. Elle ne prend aucun paramètre et ne retourne rien. Quand elle se termine, le programme s'arrête.
{ }
Le corps. L'accolade ouvrante doit rester sur la même ligne : Go insère un point-virgule invisible en fin de ligne, et une accolade renvoyée à la ligne suivante casse la compilation.
'\n'
Le retour à la ligne. Il n'est jamais ajouté automatiquement : c'est toi qui décides où la ligne se termine.

Plusieurs imports

main.gobloc d'imports
import (
	"github.com/01-edu/z01"
	"mon-projet/outils"
)

Écrire une bibliothèque

Un fichier dont le paquet n'est pas main ne s'exécute pas : il expose des fonctions à d'autres fichiers.

outils/texte.gopaquet bibliothèque
package outils

func FirstRune(s string) rune {
	for _, r := range s {
		return r
	}
	return 0
}
À retenir

La casse de la première lettre décide de la visibilité. FirstRune (majuscule) est utilisable depuis un autre paquet ; firstRune (minuscule) reste privé au fichier d'origine. Il n'existe ni public ni private en Go.

Piège

Un import ou une variable déclarés mais non utilisés sont des erreurs de compilation, pas des avertissements. Go refuse le code mort : supprime la ligne, ou consomme la valeur avec _.

Démarrer / Afficher du texte

Afficher du texte

L'affichage repose sur une seule primitive : z01.PrintRune écrit un caractère. Tout le reste — chaînes, nombres, sauts de ligne — se construit à partir d'elle.

z01.PrintRune('A')
z01.
Le paquet importé. Le point signifie « prends ce qui se trouve dedans ».
PrintRune
La fonction. Elle prend une rune et l'écrit sur la sortie standard, sans rien ajouter.
'A'
Quotes simples = une rune, un caractère unique. "A" avec des guillemets doubles serait une string, et le type ne correspondrait pas.

Les trois fonctions de base

Elles reviennent dans tous les exemples du manuel. Elles sont à connaître de mémoire.

affichage.gola base de tout
// Affiche une chaîne complète, caractère par caractère.

	for _, r := range s {
		z01.PrintRune(r)
	}
}

// Revient à la ligne.
func NewLine() {
	z01.PrintRune('\n')
}

// Affiche un entier, signe compris.

		z01.PrintRune('-')

			PrintStr("9223372036854775808")
			return
		}
		n = -n
	}
	if n > 9 {
		PrintNbr(n / 10)      // les chiffres de gauche d'abord
	}
	z01.PrintRune(rune(n%10) + '0')
}

Anatomie de la ligne clé

z01.PrintRune(rune(n%10) + '0')
n % 10
Le modulo : le reste de la division par 10, c'est-à-dire le dernier chiffre. 407 % 10 vaut 7.
rune( … )
Conversion de type. n%10 est un int, PrintRune attend une rune. Go n'accepte aucune conversion implicite : elle s'écrit toujours.
+ '0'
Le décalage ASCII. Le caractère '0' vaut 48, donc 7 + 48 = 55, et 55 est le code du caractère '7'. C'est la formule chiffre → caractère.
n / 10
Division entière entre deux int : 407 / 10 vaut 40. Elle retire le dernier chiffre. Modulo + division, c'est l'outil universel pour parcourir les chiffres d'un nombre.
if n > 9
L'appel récursif avant l'affichage inverse l'ordre : les chiffres sortent de gauche à droite, alors que le modulo les produit de droite à gauche.
Piège

z01.PrintRune(7) n'affiche pas « 7 » : il envoie le caractère de contrôle n° 7 (invisible). Un nombre devient un caractère seulement avec + '0'.

Bases du langage / Variables

Variables

Trois façons de créer une variable, une seule à retenir vraiment : :=.

Les formes de déclaration
x := 42
Déclaration courte. Crée x et déduit son type de la valeur (int ici). Utilisable uniquement à l'intérieur d'une fonction. C'est la forme employée presque partout.
var x int = 42
Forme longue. Utile quand le type doit être imposé, ou hors de toute fonction (niveau paquet).
var x int
Sans valeur : Go affecte la valeur zéro du type. Il n'existe jamais de mémoire non initialisée en Go.
const Max = 100
Constante, figée à la compilation. Toute tentative de modification est refusée par le compilateur.
x = 43
Réaffectation : un seul =. La variable doit déjà exister.
a, b := 1, 2
Déclaration multiple. La partie droite est entièrement évaluée avant d'être affectée — c'est ce qui rend possible a, b = b, a.

L'identifiant vide : _

Le tiret bas est une destination qui jette la valeur. Il permet d'ignorer ce qu'on ne veut pas, sans déclencher l'erreur « déclarée et non utilisée ».

Piège — la variable masquée

À l'intérieur d'un bloc, x := 5 crée une nouvelle variable qui masque celle du dessus au lieu de la modifier. Les changements sont alors perdus à la sortie du bloc. Pour modifier la variable existante, utilise x = 5.

Go est strict : deux types différents ne se mélangent jamais, même quand ils représentent la même chose. Toute conversion s'écrit.

Convertir

La syntaxe est toujours la même : Type(valeur).

Piège — string(entier)

string(65) ne produit pas "65" mais "A" : Go interprète l'entier comme un code de caractère. Pour obtenir la représentation décimale d'un nombre, il faut construire la chaîne chiffre par chiffre — voir Itoa.

Piège — types mélangés

var a int = 3 plus var b float64 = 1.5 : écrire a + b ne compile pas (mismatched types). Il faut float64(a) + b. Même chose entre int et rune, ou entre byte et int.

Limites et débordement

Un int 64 bits va de -9223372036854775808 à 9223372036854775807. Au-delà, il repart à l'autre bout sans aucun avertissement.

overflow.gole débordement est silencieux

n = n + 1                 // devient -9223372036854775808

// Conséquence pratique : une accumulation du type
// res = res*10 + chiffre
// déborde dès que le résultat dépasse la limite.
À retenir

Un algorithme qui réduit un nombre (n /= 10) ne déborde jamais. Un algorithme qui le reconstruit (n = n*10 + c) déborde dès qu'on approche la limite. Quand une valeur peut être grande, cherche une solution qui ne recompose rien.

Le court-circuit

Dans A && B, si A est faux, B n'est jamais évalué. Cette garantie sert à protéger un accès mémoire.

courtcircuit.gol'ordre des tests compte
if i < len(s) && s[i] == 'a' {    // sûr : s[i] n'est lu que si i est valide
}

if s[i] == 'a' && i < len(s) {    // dangereux : plantage si i dépasse
}

Priorité

Du plus fort au plus faible : * / %, puis + -, puis les comparaisons, puis &&, puis ||. En cas de doute, mets des parenthèses : elles ne coûtent rien.

Cas concret

	if i%15 == 0 {
		PrintStr("FizzBuzz")
	} else if i%3 == 0 {
		PrintStr("Fizz")
	} else if i%5 == 0 {
		PrintStr("Buzz")

		PrintNbr(i)

Pourquoi tester 15 en premier ? Parce que 15 est divisible par 3 et par 5 : si i%3 était testé avant, 15 tomberait dans « Fizz » et n'atteindrait jamais le cas combiné. Dans une chaîne else if, le cas le plus restrictif passe toujours en tête.

Bases du langage / Conditions

Conditions

Deux constructions : if pour un test, switch pour une liste de cas.

if x > 10 { … } else { … }
if
Exécute le bloc suivant seulement si la condition vaut true.
x > 10
La condition. Sans parenthèses autour, contrairement au C ou à Java. Elle doit produire un bool : if x avec x entier ne compile pas.
{ }
Accolades obligatoires, même pour une seule instruction. L'ouvrante reste sur la ligne de la condition.
else
Doit être collé à l'accolade fermante précédente : } else {. Sur une nouvelle ligne, c'est une erreur de syntaxe.
else if
Enchaîne les cas. Dès qu'un cas est vrai, tous les suivants sont ignorés.

Une variable peut naître dans le if. Sa portée se limite alors au if et à son else.

Bases du langage / Boucles

Boucles

Go n'a qu'un seul mot-clé de répétition : for. Il n'existe ni while ni do…while — les quatre formes ci-dessous les remplacent toutes.

Anatomie de la boucle à compteur

for i := 0; i < 10; i++ { }
for
Le mot-clé de répétition. Il annonce : « répète le bloc entre accolades ». Employé seul, sans rien après lui, il boucle indéfiniment.
i := 0
L'initialisation. Exécutée une seule fois, avant le premier tour. Elle crée le compteur et le met à 0 — les index commencent à 0 en Go. Ce i n'existe que dans la boucle : après l'accolade fermante, il a disparu.
;
Le séparateur. Les trois parties sont séparées par des points-virgules, obligatoires même quand une partie est vide.
i < 10
La condition de continuation. Testée avant chaque tour. Tant qu'elle est vraie, on refait un tour ; dès qu'elle est fausse, on sort. < 10 produit les valeurs 0 à 9, soit 10 tours. Avec <= 10 il y en aurait 11 — la cause n° 1 des dépassements d'index.
i++
Le post-traitement. Exécuté à la fin de chaque tour, juste avant de retester la condition. i++ équivaut à i = i + 1. C'est lui qui fait avancer le compteur : sans lui, la condition resterait vraie indéfiniment. On peut y mettre autre chose : i += 2, i--, i *= 2.
{ }
Le corps. Le code répété, qui peut lire et modifier i. break en sort immédiatement ; continue saute au tour suivant, en passant tout de même par i++.

La ligne entière, en situation

Chaînes, runes, octets

Une string est une suite d'octets immuable. On ne modifie jamais une chaîne : on en construit une nouvelle.

Pourquoi len n'est pas le nombre de caractères

Go stocke le texte en UTF‑8 : un caractère ASCII occupe 1 octet, un caractère accentué en occupe 2, un emoji jusqu'à 4.

		if r >= 'a' && r <= 'z' {

Récursivité

Une fonction qui s'appelle elle-même. Deux ingrédients obligatoires — jamais un seul.

  1. Le cas d'arrêt. La situation où la fonction répond sans se rappeler. Sans lui, le programme s'écroule sur un stack overflow.
  2. L'appel réduit. On se rappelle sur un problème strictement plus petit, qui se rapproche du cas d'arrêt à chaque tour.

func Factorial(n int) int {

func Fibonacci(n int) int {
	if n < 2 {
		return n
	}
	return Fibonacci(n-1) + Fibonacci(n-2)

La bonne façon de raisonner

Ne déroule jamais tous les appels dans ta tête. Pose-toi une seule question : « en supposant que la fonction soit correcte pour n-1, est-ce que ma ligne la rend correcte pour n ? » Si oui, et qu'un cas d'arrêt existe, la fonction est juste.

Exercice 1

Afficher les chiffres d'un entier par ordre croissant. Toutes les valeurs possibles du type int doivent être prises en compte, à l'exception des nombres négatifs. La conversion en int64 n'est pas autorisée.

Décoder l'énoncé avant d'écrire

  1. « affiche » → la fonction ne retourne rien. Toute la sortie passe par z01.PrintRune.
  2. « par ordre croissant » → 321 doit produire 123. Les répétitions restent : 1231 donne 1123.
  3. « toutes les valeurs possibles » → jusqu'à 9223372036854775807. Donc aucune opération qui fait grandir le nombre.
  4. « int64 interdit » → c'est l'indice. La contrainte vise la parade de ceux qui veulent reconstruire un nombre trié. Il ne faut donc jamais reconstruire de nombre.
  5. « sauf les négatifs » → aucun signe à gérer.
La fausse bonne idée

Le réflexe naturel : extraire les chiffres, les trier, puis recomposer avec res = res*10 + chiffre avant d'appeler PrintNbr(res). Sur 9223372036854775807, cette multiplication déborde et produit un résultat négatif absurde. Élargir le type ne réglerait rien : il existera toujours une valeur trop grande. La solution consiste à ne recomposer aucun nombre et à afficher les chiffres directement.

La stratégie : compter, puis afficher

Il n'existe que dix chiffres possibles. Plutôt que de trier une liste, on utilise dix compteurs. Une passe sur le nombre les remplit ; une passe de 0 à 9 les vide dans l'ordre. C'est un tri par comptage : aucune comparaison, aucun débordement, une seule lecture du nombre.

package main

import "github.com/01-edu/z01"

func PrintDigitsInAscendingOrder(n int) {
	if n == 0 {
		z01.PrintRune('0')
		return
	}

	compte := [10]int{}          // compte[3] = nombre de "3" dans n

	for n > 0 {
		compte[n%10]++           // le dernier chiffre incrémente sa case
		n /= 10                  // puis on le retire
	}

	for chiffre := 0; chiffre < 10; chiffre++ {
		for i := 0; i < compte[chiffre]; i++ {
			z01.PrintRune(rune(chiffre) + '0')
		}
	}
}

Anatomie, dans l'ordre d'exécution

Chaque morceau, un par un
if n == 0
Le cas limite. La boucle for n > 0 ne s'exécuterait pas du tout pour 0, et la fonction n'afficherait rien. On traite ce cas séparément.
return
Un return nu : la fonction ne déclare aucun type de retour. Il sert uniquement à sortir immédiatement.
[10]int{}
Un tableau de taille fixe, index 0 à 9. Toutes les cases valent 0 automatiquement. L'index et le chiffre coïncident : compte[7] compte les 7. Une slice ferait le même travail, mais la taille est connue et ne changera jamais.
for n > 0
Forme « while » du for : une condition seule. On boucle tant qu'il reste des chiffres. La division entière finit toujours par ramener n à 0 : la terminaison est garantie.
compte[n%10]++
Trois opérations en quinze caractères. n%10 extrait le dernier chiffre (0 à 9) ; ce chiffre sert directement d'index ; ++ incrémente la case. Aucun tri, aucune comparaison.
n /= 10
Division entière : n = n / 10. Elle supprime le chiffre qu'on vient de compter : 9807 → 980 → 98 → 9 → 0. Le nombre ne fait que rétrécir : le débordement est impossible.
for chiffre := 0; chiffre < 10
C'est ici que naît l'ordre croissant. On visite les cases de 0 vers 9, donc les petits chiffres sortent avant les grands. Rien d'autre ne trie dans ce programme.
for i := 0; i < compte[chiffre]
La boucle interne répète le chiffre autant de fois qu'il apparaît. Si la case vaut 0, elle ne tourne pas : le chiffre absent est ignoré sans test supplémentaire.
rune(chiffre) + '0'
Conversion int → rune obligatoire, puis décalage ASCII pour obtenir un caractère imprimable.

Les erreurs silencieuses

Celles qui ne déclenchent aucun message : le programme tourne, mais le résultat est faux.

Le saut de ligne oublié

La sortie paraît identique dans le terminal mais diffère d'un octet.

PrintRune(n) sans + '0'

Envoie un caractère de contrôle invisible : la ligne semble vide.

len sur de l'UTF-8

Compte des octets, pas des caractères. Utiliser range.

<= au lieu de <

Un tour de boucle en trop, ou un dépassement d'index.

Débordement d'entier

Une multiplication trop grande repart en négatif, sans avertissement.

Variable masquée

:= dans un bloc crée une nouvelle variable au lieu de modifier l'ancienne.

append non réaffecté

Modifier une slice dans une fonction sans la retourner perd les ajouts.

Ordre de map

Le parcours change à chaque exécution : la sortie n'est pas reproductible.

Méthode de déblocage

  1. Écrire la signature : nom, types des paramètres, type de retour. Cela fixe une bonne partie du problème.
  2. Traiter l'exemple à la main, sur papier, caractère par caractère. Noter la sortie attendue exacte.
  3. Nommer le motif : parcours, accumulateur, deux curseurs, comptage, récursion. Il y en a cinq, pas cinquante.
  4. Écrire la boucle sans chercher à optimiser. La faire marcher sur le cas normal.
  5. Ajouter les cas limites : chaîne vide, zéro, un seul élément, valeur maximale, valeur négative.
  6. Relire la sortie attendue une dernière fois, puis passer gofmt.

Les cinq motifs qui résolvent presque tout

Parcours

for _, r := range s — tester ou transformer chaque élément.

Accumulateur

res := "" puis res += … — construire une sortie.

Deux curseurs

i := 0, j := len-1 — inverser, comparer, détecter un palindrome.

Comptage

[10]int{} ou une map, puis t[v]++ — trier, dédoublonner, mesurer.

Modulo & division

n%10 et n /= 10 — tout ce qui touche aux chiffres d'un entier.
